# 让「不在本机 tmux 里」的 agent 也能进 hub

> 典型场景:服务器上跑着一堆 `cc-*`,而你**笔记本上的 Claude Code** 也想加入互发消息。

## 为什么原样不行

hub 靠 `tmux send-keys` 投递消息,收件人**必须是本机的一个 tmux 会话**。笔记本上的 agent:

- **发出去**勉强可以(ssh 过来调 `hub say`),但 `$TMUX` 为空 → 被标成「中控」→
  `ask` 生成的回信命令是 `hub say 中控`,而根本没有 `cc-中控` 会话 → **对方回不过来**。
- **收进来**完全不行 —— 它不是本机 tmux 会话,`hub ls` 看不见,`hub say` 也投不到。

## 做法:给它在服务器上开一个「信箱会话」

```
笔记本 Claude Code ──ssh──► hub say/ask ──► 服务器上的 cc-xxx
        ▲                                          │
        │  ssh 读 jsonl                            │ hub say local
        └────── cc-local(信箱会话) ◄───────────────┘
```

信箱 = 一个占着 `cc-local` 这个名字的 tmux 会话,里面跑 `hub-inbox`:它把 send-keys
送来的每一行落盘成 jsonl,笔记本那边经 ssh 取走。对 hub 来说它和普通 agent 没区别。

## 三个部件

| 部件 | 装在哪 | 作用 |
|---|---|---|
| `hub` 的 `HUB_SELF` 支持 | 服务器 | 让远程参与者能声明「我是 cc-local」,回信才有去处 |
| `hub-inbox` / `hub-inbox-read` | 服务器 | 信箱本体 + 取信 |
| `hub`(本地包装) | 笔记本 | 把命令经 ssh 转发,自动带上 `HUB_SELF` |

### 服务器侧

```bash
install -m755 hub.sh ~/.local/bin/hub                    # 带 HUB_SELF 支持的版本
install -m755 hub-inbox hub-inbox-read ~/.local/bin/
install -m644 'hub-inbox@.service' 'hub-inbox@.timer' /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now hub-inbox@local.timer
```

`hub-inbox@.timer` 每 2 分钟对账一次:服务器重启或会话被误杀,信箱都会自动回来。

### 笔记本侧

```bash
install -m755 hub-local.sh ~/bin/hub          # 确保 ~/bin 在 PATH
echo '<你的 ssh 别名>' > ~/.hub-host          # 或 export HUB_HOST=<别名|user@host>
# export HUB_NAME=local                       # 可选:改我在 hub 里的名字(默认 local → cc-local)
hub up                                        # 确保服务器上的信箱活着
```

脚本本身不写死任何主机 —— 连哪台由 `~/.hub-host` 或 `HUB_HOST` 决定,便于直接分发。

## 用法

笔记本上和服务器上**命令完全一致**,另加 `inbox` 系列:

```bash
hub ls                       # 服务器上所有 cc-*(含我自己 cc-local,标着「← 我在这」)
hub peek <cc> [n]            # 看某个 agent 的屏幕
hub say  <cc> "消息"
hub ask  <cc> "消息"         # 要求回信 → 回信落进我的信箱
hub inbox                    # 取未读(读完标已读)   ← 最常用
hub inbox --peek             # 偷看未读,不标已读
hub inbox --all              # 全部历史
hub inbox --count            # 只看未读条数
hub up                       # 信箱没了就拉起来
```

服务器上的 agent 什么都不用改,照常:

```bash
hub say local "……"          # 发给笔记本
hub ask local "……"          # 并要求它回信
```

## 两个实现上的坑(改之前先看)

1. **信箱必须画出 Claude 输入框的样子。** hub 的 `_ready()` 护栏有两道:末尾几行要有 `❯`,
   且同一段里要能匹配到 `⏵⏵|bypass permissions|────────|╭─|╰─` 之一(用来挡住 starship
   那类同样拿 `❯` 当提示符的普通 shell)。只打个 `❯` 会被判「不在输入框」而拒发。
   而且框要**顶到屏幕底部** —— 护栏只看 `capture-pane` 的末尾几行,框停在上方、下面全是
   空行一样过不了。

2. **`hub-inbox@.service` 不能加 `RemainAfterExit=yes`。** 加了它跑完一次就停在 active,
   timer 之后再触发时 systemd 认为「已经在运行」而跳过 → 会话被杀也补不回来。
   改 unit 后记得 `systemctl stop` 一次再测,否则旧实例的状态会让你以为新配置没生效。

## 已知边界

- 信箱是**单向落盘**的:它不会自动"读"消息给远程 agent 听,得那边主动 `hub inbox` 取。
  也就是说笔记本上的 agent 不会被实时打断,更像收邮件。
- `hub peek local` 看到的是信箱屏幕(最近几条 + 输入框),不是笔记本上 Claude 的真实屏幕。
- 消息里的换行会被 hub 压成空格(它本来就这样),长内容照旧先落文件再发路径。
