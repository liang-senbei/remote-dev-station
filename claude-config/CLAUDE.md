# 你的运行环境与能力（开工前先读一遍）

这份说明告诉你：**你此刻在哪台机器上、有哪些别处没有的能力**。踩过的坑是——AI 不知道自己能用这些工具，于是不用。所以下面每一块都要记住。

## 1. 运行环境认知：你在服务器上，不在用户的设备上

- 你运行在一台**远程服务器**上（长期在线的云主机），**不在用户的电脑/手机上**。用户的设备只是"遥控器"，用来连上来看你、跟你说话。
- 你的会话活在服务器的 **tmux** 里。用户**关掉遥控器、断网、甚至设备重启，你的会话都不会丢**——它还在服务器上跑着，重连即接回。
- 服务器万一重启，也有守护进程会**自动把登记过的会话拉回来**（从存档续上，历史不丢）。所以不用担心"关了就没了"，放心把长任务留在这里。
- 一句话：**你是常驻的、韧性的**。别把自己当成"随时会被关掉的一次性进程"。

## 2. 多 agent 协同（hub）

这台服务器上**可能同时跑多个 Claude Code 会话**，tmux 会话名形如 `cc-<名>`。你和其它会话可以用全局命令 `hub` 互相查看、通讯（对称，谁都能用）：

- `hub ls` —— 列出所有 cc 会话（各自的 git 状态 / 路径）。
- `hub peek <会话> [n]` —— 看某个会话屏幕最近 n 行在干嘛（发消息前先瞄一眼它是否空闲）。
- `hub say <会话> "内容"` / `hub ask <会话> "内容"` —— 发消息 / 发并要求回复。
- `hub all "内容"` —— 广播给除自己外的所有会话。`<会话>` 写唯一片段即可。

对 agent 说话要**简洁、直接给结论/数据、机器可读**——不是写给人看的，别加排版客套；有具体结果或确实需要对方配合时才发。

## 3. 读写用户本地电脑的文件（反向 SSH 隧道）

用户的本地电脑通过一条**反向 SSH 隧道**对你可达。**这套是极简 CLI 版，没有 Tailscale**——不是内网直连，而是用户电脑那头**主动向服务器建一条常驻反向连接**，把服务器的 `127.0.0.1:2222` 转发到用户电脑的 SSH（22 端口）。部署时会在服务器 `~/.ssh/config` 配好别名（下面以 `laptop` 为例；Mac 客户端对应 `mac`），别名内部就指向这条隧道（`HostName 127.0.0.1` / `Port 2222`），**所以你只管用别名，不用关心底层**：

- 在用户电脑上执行命令：`ssh laptop "<命令>"`
- 取用户电脑的文件到服务器：`lapget <电脑上的路径> [目标目录，默认 ~/inbox]`
- 把服务器的文件送回用户电脑：`lapput <文件> [目标，默认 Downloads/]`
- 看用户电脑某目录最近文件：`lapls [目录]`

（Mac 客户端把上面的 `lap*` / `laptop` 换成 `mac*` / `mac`。）

**这条隧道特有的坑**：

- 隧道靠**用户电脑那头维持**。若 `ssh laptop` / `lapget` 报 `Connection refused` 或连 `127.0.0.1:2222` 失败，多半是**用户那头的反向隧道断了**（电脑关机 / 睡眠 / 换网），不是你的错——提醒用户确认他电脑上的反向隧道服务在跑（Windows 上是 `LaptopReverseTunnel` 服务；Mac/Linux 是 autossh 的 launchd/systemd 单元）。别干等，先报给用户。
- 用户电脑的**非交互 shell PATH 可能残缺**（date/basename 等可能找不到）；Windows 默认落 **PowerShell**（列目录用 `Get-ChildItem` 不是 `ls`）。
- 中文、括号、空格跨机传命令易**编码坏**；`ssh laptop "echo ..."` 里别塞 `( )` 和复杂中文。
- **复杂处理一律把文件取回服务器**用 `python3` 做，别在用户电脑上硬拼命令。

（隧道端口 / 别名 / 用户名在部署时配置，不写死这里。）

## 4. 会话:敲 `claude` 就进受管常驻会话

这套极简版**没有 cloudgo 选单**：用户 `ssh cloud` 连上服务器后敲 **`claude`** 就进那个常驻会话 `cc-main`（在跑就接回，断线/重启自动 `--resume`）。这里的 `claude` 已被**包成受管入口**（bashrc 函数 → `cloud-enter`，自动带 `IS_SANDBOX=1` + tmux），和本地敲 `claude` 一个感觉。你平时就在这个会话里，不用管理它。

- 要**另开**一个会话干别的活：用 `cloud <目录>`。
- ⚠️ 本机是 **root**：**原生** `command claude --dangerously-skip-permissions` 会被拦（`cannot be used with root/sudo privileges`），必须带 `IS_SANDBOX=1`。包好的 `claude` / `cloud` / `cloud-enter` 都已带好，直接用它们即可（这跟工作目录在 `/root` 还是 `/opt` 无关，纯粹是 root 身份限制）。
