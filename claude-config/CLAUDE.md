# 你的运行环境与能力（开工前先读一遍）

这份说明告诉你：**你此刻在哪台机器上、有哪些别处没有的能力**。踩过的坑是——AI 不知道自己能用这些工具，于是不用。所以下面每一块都要记住。

## 1. 运行环境认知：你在服务器上，不在用户的设备上

- 你运行在一台**远程服务器**上（通常是长期在线的云主机），**不在用户的笔记本/台式机/手机上**。用户的那些设备只是"遥控器"，用来连上来看你、跟你说话。
- 你的会话活在服务器的 **tmux** 里。用户**关掉遥控器、断网、甚至设备重启，你的会话都不会丢**——它还在服务器上跑着，重连即接回。
- 服务器万一重启，也有守护进程会**自动把登记过的会话拉回来**（从存档续上，历史不丢）。所以不用担心"关了就没了"，放心把长任务留在这里。
- 一句话：**你是常驻的、韧性的**。别把自己当成"随时会被关掉的一次性进程"。

## 2. 多 agent 协同（hub）

这台服务器上常常**同时跑多个 Claude Code 会话**，每个项目一个，tmux 会话名形如 `cc-<项目名>`。你和其它会话可以用全局命令 `hub` 互相查看、通讯（对称，谁都能用）：

- `hub ls` —— 列出所有 cc 会话（各自的 git 状态 / 路径）。
- `hub peek <会话> [n]` —— 看某个会话屏幕最近 n 行在干嘛（发消息前先瞄一眼它是否空闲）。
- `hub say <会话> "内容"` —— 给某会话发消息 / 回信。
- `hub ask <会话> "问题"` —— 发消息并要求对方回复（对方会用 `hub say` 回你）。
- `hub all "内容"` —— 广播给除自己外的所有会话。
- `<会话>` 写唯一片段即可（不必写全名）。

收到形如 `[HUB·agent间通讯] cc:X → 你…` 的消息，就是**另一个会话在跟你对接**：照它说的做或答，回信执行 `hub say X "…"`。对 agent 说话要**简洁、直接给结论 / 数据 / 字段、机器可读**——这是 agent 之间的通讯，不是写给人看的，别加排版和客套。别刷屏：有具体结果、或确实需要对方配合时才发。

## 3. 读写用户本地设备的文件（反向通道）

用户的本地设备通过一条**反向通道**对你可达。用户把某个本地文件的路径告诉你，你就能**自己把它取过来处理、也能把结果送回去**，不用来回让用户手动拷贝。用法（部署时会为每台本地设备配好一个别名，下面用 `<本地别名>` 代指）：

- 在本地设备上执行命令：`ssh <本地别名> "<命令>"`
- 取本地文件到服务器：用配套的取文件桥接命令（如 `<别名>get <本地路径>`）。
- 把服务器上的文件送回本地：用配套的送文件桥接命令（如 `<别名>put <文件>`）。
- 取用户刚粘贴/截的图：用配套的取截图桥接命令。

注意几个坑：

- 本地设备的**非交互 shell PATH 可能残缺**（`date`/`basename` 等常用命令可能找不到），别假设都在。
- 中文、括号、空格在跨设备传命令时容易**编码出错**；`ssh <别名> "echo ..."` 里尽量别塞括号 `( )` 和复杂中文。
- **复杂处理一律拉回服务器做**：把文件取回来，用服务器上的 `python3` 处理，别在本地设备上硬拼命令。

（具体别名、地址在部署时配置，不写死在这里。）

## 4. 会话管理：一定用 cloud* 命令开会话，别直接敲 claude

开 / 切 / 管会话统一走这套命令（它们保证会话被登记、断线能自动救回）：

- `cloudgo` —— **会话总入口菜单**：平铺列出所有运行中的会话（带最近活动、实时画面预览），选一个回车进入。
- `cloudnew <目录>` —— 在指定目录**新建**一个会话（会问你起名，名字进 tmux 名 + Claude 显示名）。
- `cloudattach <会话名>` —— **接回**某个已存在的会话。
- `cc-agents` —— **指挥中心**：一屏看所有 agent 会话的状态。

**关键规矩：开会话一定用上面的 cloud* 命令（或遥控端界面上的"会话/新建"按钮），别直接在终端敲 `claude`。** 直接敲的会话不受管理、不登记，断线就丢、重启不恢复——等于白干。
